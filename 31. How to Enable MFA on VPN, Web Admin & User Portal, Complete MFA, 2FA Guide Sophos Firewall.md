Configure Multi-Factor Authentication (MFA) for Sophos Firewall Users
📘 Overview

Multi-Factor Authentication (MFA) adds an additional layer of security beyond a username and password.

A password can be compromised, leaked, shared, or discovered by an unauthorized person. When MFA is enabled, a user must provide an additional authentication factor, such as a one-time password (OTP) generated by an authenticator application.

This additional security layer helps protect administrative interfaces, user portals, VPN access, and other services exposed through the Sophos Firewall.

MFA is particularly important for organizations where users work remotely. A compromised user password should not be sufficient for an attacker to access company systems and networks.

Why MFA Is Important

Consider a situation where a user's password has been:

Compromised.
Leaked.
Shared with another person.
Discovered by someone who obtained the password from another location or source.

Without MFA, the compromised password may be sufficient to authenticate to a protected service.

With MFA enabled, the attacker also needs the additional authentication factor.

For example:

The user enters their username.
The user enters their password.
The user provides the OTP generated by the authenticator application.
Access is granted only after the additional authentication factor is successfully validated.

This additional layer helps reduce the risk associated with compromised passwords.

Important: MFA does not replace strong passwords. It provides an additional authentication layer when passwords are compromised.

Where Should MFA Be Enabled?

MFA should be considered for all appropriate access points, particularly in environments where administrative or remote access is available.

Common examples include:

Sophos Firewall administrative access.
Sophos Firewall user portal access.
VPN portal access.
SSL VPN access.
Remote user access.
Other security-sensitive services.

If you administer a Sophos Firewall, MFA should be enabled for the firewall's administrative account.

For organizations with stronger security requirements, MFA should also be applied to users.

This is particularly important when users access VPN services from home.

MFA for Small, Mid-Size, and Large Organizations

Small organizations may not always implement MFA at the user level.

However, mid-size and large organizations should strongly consider enforcing MFA for VPN users and other remote-access users.

Remote users represent an important security consideration because they may be accessing company resources from outside the corporate network.

An organization should not allow a single compromised user account to result in significant loss of company data or compromise of systems and networks.

⚙️ Configure MFA in Sophos Firewall

From the Sophos Firewall dashboard, go to:

Authentication → Multi-Factor Authentication

Groups and users may already have been configured as part of the existing firewall configuration.

The Multi-Factor Authentication (MFA) Settings section contains the MFA configuration options.

Before enabling MFA, understand the difference between administrative MFA and user MFA.

Configure MFA for the Administrator Account

The MFA settings under Authentication are primarily related to users.

To enable MFA for the administrator account, use the device-access configuration.

Go to:

Administration → Device Access

Scroll down to locate the administrator-related MFA option.

Enable MFA for the administrator account and apply the configuration.

After MFA is enabled, the administrator will be required to provide an OTP when signing in.

Note: Administrative MFA is configured separately from the user-level MFA configuration discussed later in this document.

Configure MFA for Users

Return to:

Authentication → Multi-Factor Authentication

The users created in Sophos Firewall fall under the user-level MFA configuration.

In a typical environment:

Approximately 99% of accounts may be standard users.
A smaller percentage may be IT personnel who have been granted administrative privileges.
An IT administrator can also be a user account and may therefore fall within the scope of user-level MFA.

The MFA configuration allows you to determine which users are required to use MFA.

Select the MFA Scope

Depending on your requirements, MFA can be applied to:

All users.
Specific users.

If MFA should apply to all users, select the appropriate all-user option.

If MFA should apply only to specific users, select the required users individually.

For example:

Select the required user.
Configure the MFA options.
Apply the configuration.
Continue with the remaining MFA configuration.
Generate the OTP Token at Next Sign-In

The configuration includes the option:

Generate OTP Token with next sign in

This option causes the OTP token to be generated when the user next signs in.

When MFA is enabled, the user must complete the required enrollment process.

The Sophos Firewall can prompt the user to complete the required MFA setup when the user connects to the VPN or accesses a protected portal.

⚠️ Important: Notify Users Before Enabling MFA

One of the most important considerations when deploying MFA is user communication.

Consider an organization with 500 users.

If all 500 users are working from home and VPN access was previously configured without MFA, enabling MFA without notifying users can cause authentication problems.

Users may not know that they need to enroll an authenticator application.

Before enabling MFA for existing remote users:

Notify the users in advance.
Explain that MFA will be enabled.
Explain that they will need an authenticator application.
Provide instructions for completing MFA enrollment.
Allow users to complete enrollment before enforcing MFA where appropriate.
Confirm that users can successfully authenticate.

Warning: Enabling MFA for remote users without communicating the enrollment requirements can result in multiple users being unable to connect to VPN services.

User Portal, Admin Portal, and VPN Portal

Sophos Firewall provides different portals for different purposes.

Understanding these portals is important when configuring MFA because MFA may need to be applied to more than one access point.

Captive Portal

The Captive Portal is used when a user needs to authenticate before accessing the internet.

The user enters their ID and password and signs in through the captive portal.

User Portal

The User Portal provides users with access to user-specific information and functions.

Depending on the configuration, the user can view information such as:

Internet usage statistics.
Internet quota.
Department information.
Applicable web policy.
Home.
Personal.
Download Client.
Email.
Other available user-related functions.

The User Portal is also relevant when configuring MFA for users.

Admin Portal

The Admin Portal is used to manage the Sophos Firewall.

In the demonstration, changing the port from 443 to 44 results in access to the Admin Portal.

VPN Portal

The VPN Portal provides VPN-related functionality.

In the demonstration, moving forward with 443 accesses the VPN portal.

These are default ports.

Note: If the default ports have been changed in your environment, the ports used to access these portals may be different.

The purpose of identifying these different portals is to understand where MFA may need to be applied.

VPN Portal Functions

A user can access the VPN Portal to download the required VPN configuration and setup files.

The user can then install the VPN client on the computer.

The VPN configuration and installation process was covered in previous videos.

The important point for this procedure is that the VPN Portal is a separate access point from the User Portal and Admin Portal.

Configure MFA for the User Portal

When configuring MFA for specific users, the User Portal is enabled by default as one of the relevant access points.

This means that MFA can be required when the selected user accesses the User Portal.

However, additional access points can also be protected.

Configure MFA for the VPN Portal

If users can access the VPN Portal to download setup or configuration files, MFA can also be required for this portal.

This provides an additional authentication layer before users can access VPN-related resources.

Configure MFA for VPN Connections

MFA can also be applied when a user connects to VPN.

This includes scenarios where the user connects through:

SSL VPN.
An IP-based remote connection.
Other configured VPN access.

If a user connects through VPN, MFA can be required in addition to the username and password.

Configure MFA for Administrative Access

If a user has administrative access to the Sophos Firewall, MFA can also be required for administrative access.

This is particularly important for IT personnel who have both:

A user account.
Administrative privileges.

The MFA options can therefore be selected for the required access points.

After selecting the required options, apply the configuration.

🔐 Expected MFA Authentication Flow

After the configuration is applied, the selected user must provide MFA when accessing the configured services.

The authentication process is:

Enter the user ID.
Enter the password.
Open the configured authenticator application.
Obtain the current OTP.
Enter the OTP.
Complete authentication.

For example, an OTP may appear as:

966069


The OTP is generated by the authenticator application and changes periodically.

Important: The OTP is separate from the user's normal password. The user must enter the current OTP generated by the authenticator application when prompted.

📱 Configure the Authenticator Application

When the user first enrolls in MFA, Sophos Firewall provides an enrollment process that includes a QR-code scanning option.

The user can use a supported authenticator application on the mobile phone.

The demonstration refers to:

Google Authenticator.
Microsoft Authenticator.

The user can use whichever supported authenticator application is convenient and available on the phone.

MFA Enrollment Procedure
Sign in to the required portal.
Start the MFA enrollment process.
Open the authenticator application on the mobile phone.
Select the option to add a new account.
Use the authenticator application to scan the QR code displayed by Sophos Firewall.
Confirm that the Sophos entry is created in the authenticator application.
The authenticator application will periodically generate a new OTP.
Select Proceed to Login when the enrollment process is complete.

After enrollment, the user must use the authenticator-generated OTP during subsequent authentication.

MFA Sign-In Procedure

After MFA has been configured, the authentication process consists of multiple steps.

The user must enter:

User ID.
Password.
MFA OTP.

The authentication flow can be summarized as follows:

User ID
   ↓
Password
   ↓
Authenticator OTP
   ↓
Authentication


For example, the OTP displayed by the authenticator application may be:

966069


The user enters the OTP when prompted.

After successful validation, the user is logged in.

Important: Do not confuse the OTP with the user's normal password. Repeatedly entering the old password when Sophos Firewall is requesting the MFA OTP will result in authentication failures.

MFA Authentication on the VPN Portal

After configuring MFA, return to the VPN Portal and test authentication.

The VPN Portal may initially request the user's normal credentials.

Enter the password first.

The MFA OTP is then requested separately.

For example:

505711


Enter the current OTP generated by the authenticator application.

If the authentication succeeds, the user can continue.

⚠️ Troubleshooting: Authentication Failed

A common issue occurs when MFA is enabled for users who have not been informed about the change.

For example:

All users are working from home.
MFA is enabled for all users.
Users are not notified.
Users attempt to connect to VPN.
The authentication process fails.
Users may assume that their username or password is incorrect.
Users may repeatedly attempt to authenticate using the existing password.

The user may see an error indicating that authentication has failed.

The user may incorrectly conclude that:

The username is incorrect.
The password is incorrect.
There is a spelling mistake.
The VPN configuration is broken.

If many users are affected simultaneously, this can result in a significant support issue.

The root cause may simply be that the users have not completed MFA enrollment.

MFA Token Management

Another important area is the MFA token configuration.

The configuration includes an Issue Token option.

The user's name can appear when an MFA token is associated with the user.

Users who are configured for MFA will have authentication tokens.

The list of issued tokens can also be viewed in the MFA configuration.

This provides visibility into the MFA tokens that have been issued to users.

Disable MFA

For testing or demonstration purposes, MFA can be disabled after it has been enabled.

In the demonstration, the configured 2FA/MFA setting is disabled after completing the test.

Note: Disable MFA only when required for testing, troubleshooting, or another approved administrative purpose. MFA should remain enabled where it is required by the organization's security policy.

🔒 Security Consideration: VPN Portal on WAN

One final configuration should be reviewed under:

Administration → Device Access

Locate the VPN Service option.

The VPN Portal should not be enabled on the WAN unless there is a specific and approved requirement to expose it externally.

This configuration is not recommended in the demonstrated scenario.

If the VPN Portal is enabled on the WAN, users may be able to access the portal by entering the static IP address and using port 443.

Warning: Review WAN-facing portal exposure carefully. Unnecessary exposure of administrative or user portals increases the externally accessible attack surface.

After configuring MFA, verify the following:

 MFA is enabled for the required administrator account.
 MFA is enabled for the required users.
 The correct users are included in the MFA scope.
 The required User Portal access is protected by MFA.
 The required VPN Portal access is protected by MFA.
 VPN authentication requires MFA where configured.

💡 Key Takeaways

MFA provides an additional security layer when passwords are compromised.

For Sophos Firewall environments, MFA should be evaluated across the appropriate access points, including:

Administrator accounts.
User accounts.
User Portal.
VPN Portal.
SSL VPN.
Remote-access scenarios.

The most important operational consideration is user communication.

If MFA is enabled without preparing users, remote users may suddenly be unable to authenticate and may report generic authentication failures.

A controlled MFA deployment should therefore include:

Identifying the users and access points that require MFA.
Configuring the MFA policy.
Communicating the change to users.
Providing authenticator enrollment instructions.
Allowing users to enroll.
Testing authentication.
Enforcing MFA.
Monitoring MFA tokens and authentication issues.
📎 Conclusion

Multi-Factor Authentication is a simple but important security control for protecting Sophos Firewall administration, user access, VPN access, and remote users.

The configuration is straightforward, but the deployment should be planned carefully.

In particular, administrators should ensure that users understand the new authentication process before MFA enforcement begins.

A successful MFA implementation protects against scenarios where a username and password alone are no longer sufficient to gain access to protected resources.
