Configure Multi-Factor Authentication (MFA) for Sophos Firewall Users
Overview

Multi-Factor Authentication (MFA) provides an additional layer of security beyond a username and password.

If a password is compromised, leaked, shared, or discovered by an unauthorized person, MFA requires an additional authentication factor before access is granted.

For example, when MFA is enabled:

The user enters the user ID.
The user enters the password.
The user provides the OTP generated by an authenticator application.
Sophos Firewall validates the authentication request.

MFA is particularly important for users who work remotely and access company resources through VPN.

[!IMPORTANT]
A compromised password should not be sufficient to access protected systems. MFA provides an additional authentication layer.

Why MFA Is Important

Passwords can be compromised in several ways:

Password leakage.
Password sharing.
Credential theft.
Password discovery from another source.
Other unauthorized disclosure.

Without MFA, a compromised password may be sufficient to access a protected service.

With MFA enabled, an attacker also needs the additional authentication factor.

For example, the additional factor can be a time-based one-time password (OTP) generated by an authenticator application.

Where Should MFA Be Enabled?

MFA should be considered for all appropriate security-sensitive access points.

For Sophos Firewall, this can include:

Administrator access.
User Portal access.
VPN Portal access.
SSL VPN access.
Remote user access.
Other protected services.

If you administer a Sophos Firewall, MFA should be enabled for the administrative account.

In mid-size and large organizations, MFA should also be considered mandatory for VPN users and other remote users.

Remote users are particularly important because they may access company resources while working from home.

[!WARNING]
A compromised remote-user account can expose company data, systems, and networks. Organizations should not rely on passwords alone for remote access.

Configure MFA in Sophos Firewall
Prerequisites

Before configuring MFA, ensure that:

Sophos Firewall is accessible.
You have administrative access to the Sophos Firewall.
The required users already exist.
VPN access is already configured where required.
Users have access to a supported authenticator application.
Remote users have been informed about the MFA deployment.
Configure MFA for the Administrator Account

Administrator MFA is configured separately from the general user MFA configuration.

Navigate to:

Administration → Device Access


Scroll down to locate the administrator MFA option.

Enable MFA for the administrator account and apply the configuration.

After MFA is enabled, the administrator is required to provide an OTP when signing in.

[!NOTE]
Administrator MFA is configured through the device-access configuration rather than the user-level MFA configuration.

Configure MFA for Users

Navigate to:

Authentication → Multi-Factor Authentication


The Multi-Factor Authentication (MFA) Settings page contains the user-level MFA configuration.

The users created in Sophos Firewall are included in the user-level MFA configuration.

A typical environment may contain:

Standard users.
IT users.
Users who also have administrative privileges.

A user with administrative privileges is still a user and can therefore fall within the scope of user-level MFA.

Select the MFA Scope

MFA can be applied to:

All users.
Specific users.

If MFA should apply to all users, select the appropriate all-user option.

If MFA should apply only to specific users, select the required users.

For a specific user:

Select the user.
Configure the required MFA options.
Select Apply.
Continue with the remaining configuration.
Generate OTP Token with Next Sign-In

The MFA configuration includes the following option:

Generate OTP Token with next sign in


When this option is enabled, the OTP token is generated when the user next signs in.

The user is then required to complete the MFA enrollment process.

Configure MFA for Different Access Points

MFA should be evaluated separately for each access point.

The following access points are relevant to the configuration:

User Portal.
VPN Portal.
VPN connections.
Admin Portal.
User Portal

The User Portal provides users with access to user-specific information and functionality.

Depending on the Sophos Firewall configuration, users may be able to view:

Internet usage statistics.
Internet quota.
Department information.
Applicable web policy.
Home.
Personal.
Download Client.
Email.
Other available user-related functions.

MFA can be applied to User Portal access.

VPN Portal

The VPN Portal provides users with VPN-related functionality.

Users can use the portal to download VPN configuration and setup files.

For example:

VPN Portal
    ↓
Download configuration file
    ↓
Download setup file
    ↓
Install VPN client


MFA can also be required when users access the VPN Portal.

Admin Portal

The Admin Portal is used to manage the Sophos Firewall.

The demonstration uses different ports to access the available portals.

For example:

443
44


Changing the port can result in access to a different portal depending on the Sophos Firewall configuration.

[!NOTE]
The ports shown in the demonstration are default/example ports. If the ports have been changed in your environment, use the configured ports instead.

Configure MFA for VPN Users

When configuring MFA for users, ensure that the required VPN-related access points are included.

For example, MFA may be required for:

User Portal access.
VPN Portal access.
SSL VPN connections.
IP-based remote connections.
Administrative access for users with administrative privileges.

Select the required MFA options and apply the configuration.

After the policy is applied, the selected user must provide MFA when accessing the configured services.

User MFA Enrollment
Authenticator Application

Users need an authenticator application to generate OTPs.

The demonstration references:

Google Authenticator.
Microsoft Authenticator.

The user can use the supported authenticator application available on their phone.

Enrollment Procedure
Sign in to the required portal.
Start the MFA enrollment process.
Open the authenticator application on the mobile phone.
Select the option to add an account.
Scan the QR code displayed by Sophos Firewall.
Verify that the Sophos entry is created in the authenticator application.
Wait for the authenticator application to generate an OTP.
Select Proceed to Login.

The authenticator application periodically generates a new OTP.

MFA Sign-In Process

After MFA enrollment, the user must provide three authentication components:

User ID
   ↓
Password
   ↓
MFA OTP
   ↓
Authentication


For example:

966069


The OTP shown above is an example from the demonstration.

The user enters the current OTP displayed by the authenticator application.

[!IMPORTANT]
The OTP is separate from the user's normal password. Do not repeatedly enter the existing password when Sophos Firewall is requesting the MFA OTP.

VPN Authentication

When the user connects to VPN after MFA has been enabled, the authentication process requires the configured credentials and MFA token.

The process is:

Connect to VPN.
Enter the user ID.
Enter the password.
Wait for the MFA/OTP prompt.
Open the authenticator application.
Enter the current OTP.
Complete authentication.

Example OTP:

505711


After successful authentication, the VPN connection can proceed.

Troubleshooting
Authentication Failed After MFA Is Enabled

A common issue occurs when MFA is enabled for remote users without notifying them.

Consider the following scenario:

An organization has 500 users.
All users are working from home.
Users already have VPN access.
MFA is enabled for all users.
Users are not informed about the MFA requirement.
Users attempt to connect to VPN.
Authentication fails.

The user may assume that the username or password is incorrect.

The user may repeatedly attempt to authenticate using the existing password.

The user may see an error such as:

Authentication failed


This can result in multiple users reporting authentication problems at the same time.

Resolution

Before enforcing MFA:

Notify users about the upcoming MFA requirement.
Explain the MFA enrollment process.
Tell users which authenticator application to use.
Provide instructions for scanning the QR code.
Confirm that users can generate an OTP.
Test VPN authentication.
Enforce MFA after users have completed enrollment.

[!WARNING]
Do not enable MFA for a large remote-user population without an appropriate communication and enrollment process.

MFA Token Management

The MFA configuration provides an Issue Token option.

The configured user's name may appear when an MFA token is issued.

Users configured for MFA have authentication tokens associated with their accounts.

The list of issued tokens can be reviewed from the MFA configuration.

This allows administrators to identify the MFA tokens that have been issued to users.

Disable MFA

For testing or demonstration purposes, MFA can be disabled after completing the configuration and validation.

The demonstrated configuration disables 2FA after testing.

[!IMPORTANT]
Do not disable MFA in production unless there is an approved administrative, troubleshooting, or maintenance requirement.

Security Considerations
Review VPN Portal Exposure

Navigate to:

Administration → Device Access


Locate the:

VPN Service


option.

Review whether the VPN Portal is enabled on the WAN.

The demonstrated configuration recommends that the VPN Portal should not be enabled on the WAN.

[!WARNING]
Unnecessary exposure of the VPN Portal on the WAN increases the externally accessible attack surface.

If the VPN Portal is enabled on the WAN, users may be able to access the portal using a static IP address and port 443.

Review WAN access carefully and disable unnecessary external access.

Validation

After configuring MFA, validate the following:

 Administrator MFA is enabled where required.
 User MFA is enabled for the required users.
 The correct MFA scope is configured.
 User Portal access requires MFA where configured.
 VPN Portal access requires MFA where configured.
 SSL VPN authentication requires MFA where configured.
 Administrative access requires MFA where configured.
 Users have enrolled their authenticator application.
 Users can scan the MFA enrollment QR code.
 Users can generate an OTP.
 Users can authenticate successfully with their user ID, password, and OTP.
 Users were notified before MFA enforcement.
 Issued MFA tokens can be reviewed.
 WAN access to the VPN Portal has been reviewed.
 Unnecessary WAN exposure has been disabled.

Best Practices

Follow these practices when deploying MFA:

Enable MFA for administrator accounts.
Identify all users who require MFA.
Identify all portals and services that require MFA.
Notify users before enforcing MFA.
Provide clear enrollment instructions.
Test MFA with a small group before deploying it broadly.
Verify VPN authentication after enabling MFA.
Monitor authentication failures after deployment.
Review issued MFA tokens.
Avoid unnecessary exposure of VPN services on the WAN.
Keep MFA enabled unless there is a valid reason to disable it.
Summary

Multi-Factor Authentication provides an additional security layer for Sophos Firewall environments.

MFA can be applied to appropriate administrative, user, VPN, and remote-access scenarios.

The primary areas discussed in this procedure are:

Administrator MFA.
User-level MFA.
User Portal MFA.
VPN Portal MFA.
SSL VPN MFA.
Authenticator-based OTP.
MFA token management.
User enrollment.
Remote-user communication.
WAN exposure of the VPN Portal.

The configuration itself is straightforward, but the deployment should be carefully planned.

The most important operational consideration is user communication. Remote users must understand that MFA changes the authentication process and that they must enroll an authenticator application before they can successfully authenticate.
