# Sophos Firewall Administration: Host Name, Web Admin Console Port, Date, Time, Time Zone, and NTP

> [!NOTE]
> This document covers several foundational Sophos Firewall administration tasks that are often overlooked when focusing on larger topics such as firewall rules, web filtering, VPN, NAT, and PAT. Although these settings are small, they can have a significant impact on administration, troubleshooting, security, logging, and operational consistency.

---

When deploying and administering Sophos Firewall, administrators typically focus on major configuration areas such as:

* Firewall rules
* Web filtering
* VPN
* NAT
* PAT

However, several smaller configuration items are equally important for reliable day-to-day administration.

This guide covers the following topics:

1. **Firewall host name**
2. **Host name best practices**
3. **Web Admin Console port**
4. **Default Web Admin Console port**
5. **Changing the Web Admin Console port**

7. **Firewall date and time**

These settings should not be ignored. An incorrect configuration can result in administrative mistakes, connectivity issues, authentication problems, inaccurate logs, or unnecessary troubleshooting.

# ⚙️ 1. Configure the Sophos Firewall Host Name

## What Is a Host Name?

A **host name** is the name assigned to a computer, server, network device, or firewall.

For a firewall, the host name provides an easy way to identify the device being administered.

Changing the default firewall host name is a recommended administrative practice, particularly in environments where multiple firewalls are deployed.

---

## Why Should You Change the Firewall Host Name?

Consider an organization with four branches.

Each branch has its own firewall, and administrators may access all four firewalls simultaneously using multiple browser tabs.

Without meaningful host names, it can become difficult to determine which firewall is currently open.

For example:

| Browser Tab | Firewall   | Potential Problem                                           |
| ----------- | ---------- | ----------------------------------------------------------- |
| Tab 1       | Firewall 1 | Administrator intends to make a configuration change        |
| Tab 2       | Firewall 2 | Similar interface makes identification difficult            |
| Tab 3       | Firewall 3 | Administrator may accidentally configure the wrong firewall |
| Tab 4       | Firewall 4 | Another branch may be affected                              |

If an administrator accidentally creates a firewall rule or changes another configuration on the wrong firewall, the resulting issue can be significantly larger than the original task.

A meaningful host name makes the firewall immediately identifiable.

---

## Recommended Host Name Approach

If your organization has multiple branches, use names that clearly identify the firewall's location or role.

For example:

```text
Branch-01
Branch-02
Branch-03
HeadOffice
```

For a High Availability (HA) deployment, the naming convention can also identify the firewall's role.

For example:

```text
HeadOffice-Primary
HeadOffice-Secondary
```

If the HA configuration uses active/active or active/passive operation, naming the devices according to their role makes administration easier.

> [!TIP]
> Use a consistent naming convention across all firewalls in the organization. Consistent names make device identification easier during administration, monitoring, troubleshooting, and incident response.

---

## Change the Firewall Host Name

To change the firewall host name:

1. Sign in to the **Sophos Firewall** administration console.
2. Go to **Administration**.
3. Select **Admin & User Settings**.
4. Locate the **Host Name** setting.
5. Enter the new host name.
6. Apply the configuration.

The firewall displays a confirmation message similar to:

> Are you sure you want to update the host name?

Confirm the change.

The firewall host name is then updated.

# 🔐 2. Configure the Web Admin Console Port

The **Web Admin Console** is used to administer Sophos Firewall through a web browser.

The administration interface uses HTTPS and listens on a configured TCP port.

The default port referenced in this documentation is:

```text
4444
```

Administrators can change this port when required.

---

## Why Change the Web Admin Console Port?

Changing the administration port can be useful in environments where administrators want to avoid exposing the default management port.

For example, employees or other users may know that the organization uses the default administration port and repeatedly attempt to access it.

Changing the port can therefore reduce exposure to casual or automated connection attempts.

> [!IMPORTANT]
> Changing the management port is not a replacement for proper security controls. Restrict administrative access using appropriate network controls, authentication, firewall policies, and other security mechanisms.

---

## Change the Web Admin Console Port

To change the Web Admin Console port:

1. Sign in to the Sophos Firewall administration console.
2. Go to **Administration**.
3. Open **Admin & User Settings**.
4. Locate the **Admin Console** settings.
5. Locate the HTTPS port configuration.
6. Change the port number.
7. Apply the configuration.

For example, if the current port is:

```text
4444
```

and you change it to:

```text
5445
```

the Web Admin Console will no longer be accessed through port `4444`.

The new port must be specified when accessing the administration interface.

For example:

```text
https://<firewall-ip>:5445
```

Replace `<firewall-ip>` with the appropriate IP address of the Sophos Firewall.

---

## Validate the Web Admin Console Port Change

After changing the port, refresh the old administration URL.

The previous URL using port `4444` will no longer load the Web Admin Console.

The browser may continue displaying a loading indicator or eventually report that the page cannot be reached.

This behavior is expected if the firewall is no longer listening for Web Admin Console connections on the previous port.

Open the administration interface using the new port instead:

```text
https://<firewall-ip>:5445
```

> [!WARNING]
> Always record the new management port before applying the change. Losing track of the configured administration port can result in unnecessary administrative downtime.

# 🕐 4. Configure Firewall Date and Time

Correct firewall time is important for reliable network and security operations.

Incorrect time can make troubleshooting more difficult and can affect the accuracy of time-dependent information.

To configure the firewall time:

1. Sign in to the Sophos Firewall administration console.
2. Go to **Administration**.
3. Select **Time**.
4. Review the available time configuration options.

Sophos Firewall provides an option to configure the time manually.

If manual configuration is selected, you can configure:

* Date
* Time

However, manual time configuration is **not recommended** for normal production operation.

---

# 🌐 5. Use NTP for Time Synchronization

Instead of manually configuring the firewall clock, use **Network Time Protocol (NTP)**.

## What Is NTP?

NTP stands for:

> **Network Time Protocol**

NTP is a protocol used to synchronize the clocks of network-connected devices.

An NTP configuration allows the firewall to automatically synchronize its:

* Date
* Time
* Clock

with an appropriate time source.

Accurate time synchronization is important for network devices because many operational and security functions depend on correct timestamps.

---

## Why Is NTP Important?

Using NTP provides automatic synchronization rather than requiring an administrator to manually maintain the firewall clock.

For example, if the firewall clock is incorrect, time-dependent information can become difficult to interpret.

Accurate time is especially useful when investigating events across multiple systems because administrators can correlate events using their timestamps.

> [!TIP]
> In an enterprise environment, use a consistent and trusted time source across network infrastructure whenever possible.

---

# 🌍 6. Configure the Time Zone

In addition to configuring the correct time, select the appropriate time zone.

The time zone determines how the configured time is represented for the firewall's location.

For example, the source material uses:

```text
Asia/Kolkata
```

for India.

India officially uses one time zone.

Other countries can use multiple time zones.

For example, Russia officially has **11 time zones**.

Different locations within the same country can therefore have different local times.

For example:

* Morning can be occurring in one location.
* Evening can be occurring in another location.
* Sunrise can be occurring in one location.
* Sunset can be occurring in another location.

For this reason, select the time zone appropriate for the firewall's location.

The configuration interface provides multiple time zone options, including entries such as:

```text
America/...
```

Select the appropriate value manually.

---

# 🛠️ 7. Configure an NTP Server

Sophos Firewall can use predefined NTP servers.

If you do not want to use the predefined NTP configuration, you can specify an NTP server manually.

A Sophos-related NTP server referenced in the source material is:

```text
0.sophos.pool.ntp.org
```

The exact NTP server does not necessarily need to be memorized.

---

## Use a Custom NTP Server

Organizations with their own internal NTP infrastructure can configure a custom NTP server.

This is particularly useful in larger enterprise environments.

For example, if the organization operates its own NTP server, the administrator can enter the server's IP address or other required details.

To configure a custom NTP server:

1. Open the Sophos Firewall administration interface.
2. Go to the time configuration.
3. Locate the NTP configuration.
4. Select the **Custom NTP Server** option.
5. Enter the required NTP server information.
6. Apply the configuration.

If you want to continue using the predefined NTP servers, select the predefined option instead.

# 🔎 8. Understanding the NTP Hierarchy

A common question is:

> Where does the NTP server itself get the correct time?

This is an interesting topic that can be explored in greater depth.

At a high level, NTP servers operate within a hierarchy.

NTP servers can synchronize time with other NTP servers, while higher-level systems can synchronize against trusted reference clocks.

Some highly accurate reference systems can use sources such as:

* GPS
* Atomic clocks
* Other highly accurate reference resources

The general concept can be represented as:

```text
Trusted Reference Clock
        │
        ▼
Higher-Level NTP Server
        │
        ▼
NTP Server
        │
        ▼
Network Devices
        │
        ├── Firewall
        ├── Router
        ├── Switch
        └── Other Systems
```

This hierarchy allows network devices to maintain accurate and consistent time.

> [!NOTE]
> In a normal office environment or for the basic Sophos Firewall configuration discussed in this guide, administrators do not need to go deeply into the NTP hierarchy. Understanding the basic synchronization concept is sufficient for this configuration.

# 🔧 9. Recommended Administrative Practices

The following practices summarize the configuration discussed in this guide.

## Host Name

* Use a meaningful firewall host name.
* Include the branch, location, or device role where appropriate.
* Use a consistent naming convention across the organization.
* Use meaningful names for primary and secondary HA firewalls.

## Web Admin Console

* Know which port is configured for the Web Admin Console.
* Document any custom management port.
* Restrict access to the management interface appropriately.
* Verify access after changing the port.
* Do not assume that changing the port alone provides complete security.

## Date and Time

* Configure the correct time zone.
* Prefer NTP synchronization over manual time configuration.
* Use a trusted NTP source.
* Consider using an organization's internal NTP server where appropriate.
* Maintain consistent time synchronization across network infrastructure.

# ⚠️ 10. Troubleshooting Considerations

## Cannot Access the Web Admin Console

If the Web Admin Console no longer loads after changing the port:

1. Verify the configured management port.
2. Confirm that you are using the new port in the browser URL.
3. Verify network connectivity to the firewall.
4. Confirm that the firewall IP address is correct.
5. Check whether the browser is still attempting to use the previous port.

For example:

```text
https://<firewall-ip>:5445
```

---

## Firewall Time Is Incorrect

If the firewall displays an incorrect time:

1. Check the configured time zone.
2. Check the configured date and time.
3. Verify the NTP configuration.
4. Verify the configured NTP server.
5. Check connectivity to the NTP server.
6. If using a custom NTP server, verify the server information.

---

## Multiple Firewalls Are Difficult to Identify

If administrators have difficulty identifying multiple firewalls:

1. Review the host name of each firewall.
2. Assign meaningful names based on branch or location.
3. For HA deployments, identify the device role.
4. Use a consistent naming convention.
